## What was added since the previous run

- **Architecture selector** in Direct Download (ARM64 / ARMv7). `arch.set` RPC persists choice in `chrome.storage.local`. Next sign-in filters profiles to matching arch.
- **Install to Device card**, ADB v2 client via `@yume-chan/adb`. Bundled at build time with `esbuild` into `src/vendor/adb-bundle.js` (~65 KB). Connects via WebUSB; shows model + Android version + serial.
- **Backup & Restore card.**
  - **Backup App List**: pulls user-installed packages from the connected device (`pm list packages -3`) and downloads a JSON file you can save.
  - **Import List**: reads a JSON file, renders a checkbox list, and downloads every selected package sequentially via the SW's `app.downloadList` RPC.
- **Per-download DNR rule cleanup**: `chrome.downloads.onChanged` listener removes cookie rules when downloads complete / interrupt. No more rule accumulation.
- **Broadcast lifecycle events**: SW emits `download.event` for `purchase`, `delivery`, `start`, `queued`, `complete`, `interrupted`, plus `list.start` / `list.itemDone` / `list.itemFail` / `list.done` for the bulk path.
- **e2e/04-backup-restore.mjs**: writes a 1-package JSON, drives `<input type="file">` via `uploadFile`, clicks the rendered "Download all selected" button, asserts ≥1 `list.start` and ≥1 `queued` event.

## Still not in (tracked, not yet implemented)

- **Merge splits + re-sign**: legacy uses `APKEditor.jar` + `apksigner`. Pure-JS merging would require a WASM build of the APK tooling. Out of scope for this milestone.
- **Direct ADB install of downloaded APKs**: today the user downloads to disk and runs `adb install-multiple` themselves. To pipe Play CDN → SW → page → ADB would mean fetching the APK bytes in the SW (not `chrome.downloads`), transferring blobs across the SW↔page boundary, and pushing via `gplaydlAdb.installSplit`. The ADB client is in place; this is purely UX wiring.
- **Auto-refresh on stale auth token**: `auth.status` reports `stale: true` after 4 h but doesn't auto-re-auth on the first 401.

These have stubs nowhere in code; they simply don't exist yet. Adding them follows the same pattern as the rest of the SW.
